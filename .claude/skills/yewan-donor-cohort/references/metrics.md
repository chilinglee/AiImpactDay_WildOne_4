# 指標定義

所有指標都在 `scripts/yewan_cohort.py` 中實作，這份文件是給人看的說明版本。若兩者不一致，以程式為準，並請修正本文件。

## 共用設定
| 名稱 | 定義 |
|---|---|
| 資料期間 | ②③ 中最早到最晚的捐款日（2025-11-01 ~ 2026-10-31） |
| 觀察截止日 `as_of` | 預設等於資料期間最後一天 |
| 天數 | 一律以日曆天計（先把時間去掉再相減） |
| 期間捐款人 | 期間內至少有一筆 ② 定期扣款或 ③ 單筆捐款的聯絡人 |
| 期間新捐款人 | 期間捐款人，且 `聯絡人建立日期` ≥ 期間開始（官網多在捐款當下建立聯絡人） |
| 首捐日期／首捐類型 | 期間內最早一筆交易的日期與類型（單筆／定期定額） |
| 年輕支持者 | 年齡為 5-9、10-14、15-19、20-24 歲；比例的分母＝已填年齡者 |
| 扣款間隔 P90 | ② 同一方案相鄰兩次扣款間隔的第 90 百分位（下限 45 天）。判斷「沒扣款＝停止」前至少要等這麼久 |

## 方案主檔（`03_定期方案主檔.csv`）——任務二的基礎
④ 一人只有一列，所以先還原「一個方案一列」：
| 欄位 | 定義 |
|---|---|
| 方案集合 | ② 的所有 `定期捐款編號` ∪ ④ 的所有 `定期捐款編號` |
| 明細有列 | 此方案出現在 ④ |
| 執行期數 | ④ 有列用 ④；沒列用 ② 交易編號後段的最大值 |
| 狀態 | ④ 有列用 ④；沒列：沉默天數 ≤ 扣款間隔 P90 →「推定進行中（明細未列）」，否則「推定停止（明細未列）」 |
| 開始日期 | ④ 有列用 ④；沒列用「期間第一次扣款日 −（期數−1）個月」推估（`開始日期為推估`=True） |
| 期間新方案 | 期間內出現第 1 期扣款，或 ④ 開始日期在期間內 |
| 停止 | 狀態 ∈ {暫停中, 已失敗, 已取消, 待處理, 推定停止（明細未列）} |
| 此人仍有其他方案在扣款 | 同一人有另一個狀態為 進行中／推定進行中 的方案 |
| 換方案(非流失) | （停止 或 已完成）且 此人仍有其他方案在扣款 → 換卡／續約，不是流失 |
| **真流失** | 停止 且 此人沒有其他方案在扣款 |
| 被動流失 | 真流失 且 狀態 ∈ {待處理, 已失敗}（扣款失敗造成，可挽回） |
| 流失類型 | 待處理→被動：第一次扣款就失敗；已失敗→被動：扣款失敗；暫停中→暫停（原因不明）；已取消→主動取消 |
| 有扣款失敗 | ④ 請款次數 > 成功次數 |
| 失敗後已恢復 | 有扣款失敗，且最近成功扣款日 > 最近失敗日期 |
| 最近成功扣款日 | max(④ 最近一筆收到日期, ② 最後一筆扣款) |
| 沉默天數 | as_of − 最近成功扣款日 |
| 靜默流失 | 狀態＝進行中，但沉默天數 > 45 天 |
| 停止或結束日期 | 已失敗/已取消→失敗或取消日期；待處理→最新建立日期；暫停中/推定停止→最近成功扣款日；已完成→結束日期 |
| 約定期數分組 | 不限期／≤6期／7-12期／13-24期／25-36期／37期以上／未知（明細未列） |
| 換方案後月額變化 | 換方案時：此人其他扣款中方案的約定金額合計 − 此方案約定金額。< 0 ＝「同時兩個方案停掉一個」或降額，人還在但每月變少 |
| 之後有加碼方案 | 同一人有另一個開始日期較晚、仍在扣款、約定金額較高的方案 |

## 任務一：輪廓
| 指標 | 定義 |
|---|---|
| 捐款型態 | 期間內只有單筆／只有定期／定期＋單筆 |
| 25 歲以下（占已填） | 年輕支持者 ÷ 已填年齡者，附 Wilson 95% 區間與年齡填寫率 |
| 檢定 | 捐款型態 × 是否 25 歲以下（卡方，只看已填年齡） |

## 任務二：定期定額留存
| 指標 | 定義 | 為什麼這樣算 |
|---|---|---|
| 觀察對象 | 期間內有扣款的方案 ＋ 期間新方案 | ④ 只收期間內有扣款的人，期間前就停的方案看不到 |
| 進入觀察期數 | 期間新方案＝0；其他＝期間內第一筆扣款的期數 | **延遲進入**：老方案不是從第 1 期開始被觀察，不能放進前面幾期的分母 |
| 第 k 期停止率（hazard） | 第 k 期真流失數 ÷（進入觀察期數 ≤ k ≤ 執行期數 的方案數） | Kaplan–Meier。第 0 期＝第一次扣款就沒成功 |
| 累積存活率 | ∏(1 − hazard) | 讀成「撐過第 k 期的機率」 |
| 危險期數檢定 | 第 0–24 期 hazard 是否相同（卡方） | 顯著＝確實有特定的危險期數 |
| 真正扣滿約定期數 | 約定總期數 > 0 且 執行期數 ≥ 約定總期數 | |
| 已完成→沒有續約 | 已完成 且 此人沒有其他方案在扣款 | 續約邀請的對象 |
| 當月成功扣款人數 | 當月 ② 有成功扣款的不重複系統編號（＝官方資料說明頁的「每月成功扣款人數」） | 對帳基準 |
| 在籍人數(首末扣款之間) | 當月介於此人第一次與最後一次扣款之間的人數（含當月剛好漏扣的人） | 月流失率的分母 |
| 月流失（以人計） | 某人最後一次定期扣款在 m 月，之後到 as_of 都沒有。距 as_of 不足扣款間隔 P90 的月份不判定 | 以人計，換卡不會被誤算 |
| 新定期捐款人 Cohort 留存 | 此人最早方案在期間內開始；以首次扣款月份分群；M_k＝第 k 個月仍有扣款的人數 ÷ Cohort 人數 | 排除期間前就在捐的人（左截斷） |

### 優先提醒名單的計分規則（一人一列，取分數最高的方案）
「此人仍有其他方案在扣款」的停止方案，一律不列入。
| 條件 | 分數 | 建議行動 |
|---|---|---|
| 已失敗／待處理，停止 ≤ 365 天 | +40 | 付款失敗挽回：說明如何用新卡重新設定 |
| 進行中但最近一次扣款失敗、尚未恢復 | +35 | 付款失敗挽回 |
| 暫停中，停止 ≤ 365 天 | +30 | 恢復邀請：分享近期救援成果 |
| 靜默流失 | +25 | 靜默關懷 |
| 推定停止（明細未列），≤ 365 天 | +20 | 先到後台確認方案狀態 |
| 扣款中且剩 0–2 期 | +15 | 續約邀請 |
| 已完成且沒有續約，≤ 365 天 | +20 | 續約邀請 |
| 已取消，≤ 365 天 | +5 | 尊重取消：只寄年度成果，不催 |
| 停止未滿 30 天 / 31–90 天 | +20 / +10 | — |
| 約定金額 ÷ 100（上限 15） | +0~15 | — |
| 已扣款 6 期以上 | +5 | — |

「建議行動」取符合條件中排在最上面的那一項；「理由」列出所有符合的條件。
上表是分析用的計分名單（`t2_優先提醒名單`）；寄給勸募科的是下面兩份（`t2_起死回生名單`、`t2_預防性提醒名單`）。

### 約定進度、失敗之後、預防性提醒
| 指標 | 定義 | 為什麼這樣算 |
|---|---|---|
| 設定期數 Cohort（`t2_設定期數Cohort留存`） | 列＝設定的約定期數（6／12／24／36／37-60／61 以上／不限期），欄＝第 k 期；值＝Kaplan–Meier 留存（延遲進入，真流失才算離開，期滿與換方案視為設限）。固定期數的列超過約定期數留空；仍在觀察的方案 < 20 也留空。另附各列「期滿後續約率」 | 回答「設定幾期的人、各期留存多少」 |
| 約定進度 | 第 k 期 ÷ 約定總期數，分 0%／1-25%／26-50%／51-75%／76-99%／100% | 不同期數的方案放在同一把尺上比較 |
| 每期流失率（依進度） | 某進度區間內真流失的期數 ÷ 經過該區間的人期數（延遲進入） | 回答「扣到約定的幾成時最容易停」 |
| 期滿續約 | 已完成的方案中，此人另有方案在扣款的比例 | 期滿＝方案自然結束，不算在 hazard 裡，要另外看 |
| 失敗之後 | 期間內最近失敗日期的方案：同方案恢復／另開方案在扣（換卡）／尚未恢復 | 「事後挽回」的成效基準 |
| 高風險期數 | 第 0–24 期中，該期停止率 95% 下界 > 平均停止率 | 只用確定高於平均的期數，避免把雜訊當危險期 |
| 預防性提醒名單 | 狀態為進行中／推定進行中，一人一列。**P1**：下一期是高風險期數。**P2**：所屬設定期數 Cohort 在他目前期數的留存率 < 60%（該格樣本不足時沿用前面最後一個有值的期數）。兩者皆符合列 P1 | 在停下來之前先溝通；P1 是馬上要碰到危險期，P2 是同類捐款人大多已經離開的階段 |
| 起死回生名單 | 狀態為已失敗／待處理／暫停中；停止日期＝最近失敗日期（若沒有，或早於此方案最後一次成功扣款，改用最近一筆收到日期）；撈取日（as_of）− 停止日期 > 3 天，且此人在停止日期之後沒有任何成功扣款（任何方案）；一人一列 | 官方資料中，失敗後回來的人全部在 0–3 天內、都是換卡另開方案；超過 3 天就不會自己回來 |
| 預計下次扣款日／建議寄送日 | 最近成功扣款日 + 1 個月；建議寄送日＝前 7 天（不早於 as_of 隔天） | 扣款前一週提醒 |

## 任務三：支持時刻
| 指標 | 定義 |
|---|---|
| 活動窗 | 活動日起 7 天；備註寫「至 M/D」的以該日為止（週年紀念品活動 4/18–5/31）。「每月第一週」展開成每月 1–7 日 |
| 活動前日均 | 活動日前 14 天的日平均 |
| 活動類型成效（`t3_活動類型成效`） | 同類活動加總：增幅＝Σ活動窗人數 ÷ Σ預期人數；顯著活動數＝校正後顯著的場次（例如電子報 13 次中 1 次）；加上單筆首捐者的 90 天再捐率、轉定期率與 95% 區間 |
| 增幅倍數／p 值 | 活動窗人數 ÷（日均 × 窗天數）；p = P(X ≥ 觀察值 \| Poisson(預期))，單尾 |
| 校正後 p 值 | p × 該指標的活動數（Bonferroni）；判定用校正後 p 值 |
| 指標 | 新捐款人（依首捐日）、新定期方案（依第 1 期扣款日或開始日） |
| 未解釋高峰 | 當日數 ≥ 10、≥ 前 28 天中位數 2 倍，且 Poisson p < 0.001；活動日前 1 天到活動窗後 2 天內找不到事件＝「（找不到）」 |
| 首捐時的活動類型 | 首捐日落在哪一類活動窗內（重疊時取較晚開始的活動），否則「無對應活動」 |
| N 天內再捐率 | 單筆首捐的新捐款人，首捐後 N 天內（不含首捐當筆）有任何捐款。只計算觀察期滿 N 天的人 |
| 轉為定期率 | 單筆首捐的新捐款人，之後出現定期扣款。⚠ 沒有限制觀察天數，期末才首捐的群組（如 9 月媒體報導）會被低估 |

## 判定規則
- 顯著水準 α = 0.05。
- 分群比較用卡方獨立性檢定，並用 **Bonferroni 校正**（p × 維度數）。
- 最小組樣本 < 30 時，判定為「樣本太少：不宜下結論」。
- 比率都附上 Wilson 95% 信賴區間。
