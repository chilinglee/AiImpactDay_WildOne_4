## 2. 任務二問題對照
| 團隊問題（行前對焦文件） | 看哪個輸出 | 判讀方式 |
|---|---|---|
| 分級的標準是什麼？依據什麼資料？ | `references/metrics.md` 的計分規則 | 規則透明、可以調整；每一分都有理由欄位 |
| 日、週、月的流失率（7 天、30 天）預警 | `t2_沉默天數分布.csv`、`t2_月流失率.csv` | 0–7 天屬正常；8–30 天觀察；31 天以上預警；超過 45 天且仍是進行中 = 靜默流失 |
| 哪些捐款者流失了？性別、年齡、鄉鎮市 | `t2_分群比較_*.csv` | **先看判定欄位**；不顯著就說「不需要分群差異化溝通」 |
| 設定期數 vs 實際失敗/暫停期數 | `t2_設定期數vs實際.csv` | 比較各設定期數的停止率和真正扣滿率 |
| 期滿後又續約、加碼 | 同上的「之後有再開方案／加碼方案」欄位 | 加碼者的特徵可以做為續約信的範本 |
| 扣款失敗但有恢復的那群人 | `t2_扣款失敗與恢復.csv`、`03_定期方案主檔.csv` | 恢復率高 → 提醒有效；未恢復的人進入名單 |
| 哪一群人可以定期提醒？ | `t2_優先提醒名單.csv` | 依「建議行動」分組寄信 |
| 第幾期最容易停止？ | `t2_停止期數.csv` + 獨立性檢定 | 檢定不顯著 → 沒有特定的危險期，提醒要持續做，不必只針對某一期 |

## 4. 從結果到行動（範本）
| 結果 | 給誰 | 什麼時候 | 說什麼 |
|---|---|---|---|
| 扣款失敗未恢復 | 名單中「付款失敗挽回」 | 失敗後 3 天內 | 感謝 + 「用新卡重新設定」的步驟說明（野灣無法直接改卡號）+ 這期款項要用在哪隻動物身上 |
| 暫停中 | 「恢復邀請」 | 每月扣款日前 | 近期救援成果 + 恢復連結 |
| 靜默流失 | 「靜默關懷」 | 沉默第 30–45 天 | 確認是否仍願意支持，並提供降額選項 |
| 即將到期／已完成 | 「續約邀請」 | 最後一期前 1 個月 | 這段時間的成果回顧 + 續約／加碼方案 |
| 單筆新捐款人 | 期間新捐款人 | 首捐後第 7–30 天 | 救援故事 + 小額定期邀請 |

## 5. 三頁簡報骨架（對應評分三個面向）
1. **問題（30%）**：官網定期定額是野灣最大的收入來源（2025 年 2,241 萬元，佔募款收入 45.7%），但公益勸募課只有 2 個人。每個月要先聯絡誰？用數字說明規模：失敗 N 個方案、靜默流失 N 個、名單 N 人。
2. **方法（40%）**：Skill 流程圖（資料 → 品質檢查 → 分析 → 可信度判定 → 名單）。展示「AI 會講的假洞察」被檢定擋下來的例子，並說明 19 個對帳測試全部通過。
3. **組織能不能用（30%）**：Demo `report.html` 和名單。回答三個問題：誰在什麼時刻打開？使用前後有何差異？還缺什麼資料、誰來補？
