# 分析劇本：問題 → 指標 → 行動

## 1. SaaS 訂閱類比
| SaaS 概念 | 野灣對應 | 本 Skill 的輸出 |
|---|---|---|
| 訂閱 | 定期定額方案（一人可以有多個） | `03_定期方案主檔.csv` |
| 月費 | 約定金額 | — |
| Logo churn | 人不再扣款（真流失） | `t2_停止期數.csv`、`t2_月流失率.csv`（以人計） |
| Plan change（不是 churn） | 換卡／續約重開方案 | `換方案(非流失)` 欄位、`t2_流失類型.csv` |
| Involuntary churn | 待處理（首扣失敗）、已失敗 | `被動流失` 欄位、`t2_扣款失敗與恢復.csv` |
| Dunning（催繳） | 扣款失敗提醒 | 名單中的「付款失敗挽回」 |
| Silent churn | 狀態是進行中，但已經沒在扣款 | `靜默流失` 欄位 |
| Renewal / Expansion | 期滿續約、加碼 | `已完成→沒有續約`、`之後有加碼方案` |
| Acquisition cohort | 首捐月份 Cohort | `t2_定期Cohort留存.csv`、`t3_新捐款人Cohort留存.csv` |
| Activation | 首捐後 30/90 天內再捐 | `t3_新捐款人後續行為.csv` |
| Campaign attribution | 活動帶來新捐款人／新方案 | `t3_活動前後.csv`、`t3_未解釋高峰.csv` |

## 3. 任務二問題對照
| 問題 | 看哪個輸出 | 判讀方式 |
|---|---|---|
| 人最常在第幾期停下來？ | `t2_停止期數.csv` | 先看危險期數檢定；顯著才說「第 X 期是危險期」，並附 hazard 與區間 |
| 哪些是被動流失、可以救回來？ | `t2_流失類型.csv`、`t2_扣款失敗與恢復.csv` | 被動流失＝扣款失敗；「換方案」那一列不需要挽回 |
| 已經停下來的人怎麼重新邀請？ | `t2_流失類型.csv` 的停止時間分布 | 停止 > 90 天的人改用「年度成果」而不是催繳 |
| 誰先被提醒、什麼時候、說什麼？ | `t2_優先提醒名單.csv` | 一人一列；照「建議行動」分工 |
| ④ 一人一列，多方案怎麼辦？ | `03_定期方案主檔.csv` | 已由 ② 還原；看 `明細有列`、`此人仍有其他方案在扣款` |
| 設定期數 vs 實際 | `t2_設定期數vs實際.csv` | 比較各組真流失率與扣滿率；看判定 |
| 哪些捐款者流失了？（年齡、性別…） | `t2_分群比較_流失.csv` | **先看判定欄位**；不顯著就說「不需要分群差異化溝通」 |

## 5. 從結果到行動（範本）
| 結果 | 給誰 | 什麼時候 | 說什麼 |
|---|---|---|---|
| 扣款失敗未恢復 | 名單「付款失敗挽回」 | 失敗後 3 天內 | 感謝 + 「用新卡重新設定」的步驟（野灣無法直接改卡號）+ 這期款項用在哪隻動物身上 |
| 暫停中 | 「恢復邀請」 | 每月扣款日前 | 近期救援成果 + 恢復連結 |
| 推定停止（明細未列） | 「先到後台確認」 | 每月一次 | 先確認狀態，再決定用哪一種信 |
| 即將到期／期滿沒續約 | 「續約邀請」 | 最後一期前 1 個月 | 這段時間的成果回顧 + 續約／加碼方案 |
| 主動取消 | 「尊重取消」 | 年度成果寄送時 | 只分享成果，不催 |
| 單筆新捐款人 | 期間新捐款人 | 首捐後第 7–30 天 | 救援故事 + 小額定期邀請 |

## 6. 三頁簡報骨架
1. **問題**：官網定期定額是野灣最大的收入來源（2025 年佔募款收入 45.7%），但公益勸募課只有 2 個人。每個月要先聯絡誰？用數字說明規模：真流失 N 個方案、其中被動流失 N、名單 N 人；並點出「④ 直接拿來用會打擾到 N 位仍在捐款的人」。
2. **方法**：Skill 流程圖（資料 → 品質檢查 → 方案還原 → 分析 → 可信度判定 → 名單）。展示「AI 會講的假洞察」被檢定擋下來的例子，並說明對帳測試全部通過。
3. **組織能不能用**：Demo `report.html` 和名單。回答官方三個問題：誰在什麼時刻打開？用之前和用之後差在哪？還缺什麼資料、誰來補、怎麼持續？
