# 野灣捐款人 Cohort 分析

## 這個 Skill 要幫誰、解決什麼
- **使用者**：野灣公益勸募科（不是資料分析師）。
- **時刻**：每月寄信/扣款失敗通知前，要決定「這個月先聯絡誰、說什麼」。
- **兩個問題**：
  - 任務二：定期定額捐款人最常在第幾期停止？哪些扣款失敗可以挽回？應該優先提醒誰？
  - 任務三：哪些事件帶來新捐款人？他們之後有沒有再捐、轉為定期？

> 核心原則：**先驗證、再下結論**。每一個數字都要附上樣本數與可信度判定；
> 判定為「不宜下結論」的差異，**不可以**寫成洞察或建議。這是本 Skill 和一般 Cohort 分析最大的不同。

## 工作流程（照順序做，不要跳步）

### Step 0：確認情境
1. 讀 `knowledge_base/` 中的野灣背景：
   - `組織概況.md`：使命、規模，以及公益勸募課只有 2 人（說明問題時用）
   - `募款與溝通管道.md`：定期定額佔募款收入 45.7%（說明重要性時用）、捐款頁規則、**換卡＝新方案**
   - `名詞對照.md`：模擬欄位和真實系統的差異（回答「還缺什麼資料」時用）
   - `捐款人溝通範例.md`：寫信件草稿時用
2. 問清楚使用者這次要回答的是任務二、任務三，或兩者都要；需要的是「報告」、「名單」，還是「簡報素材」。

### Step 1：跑分析管線（不要自己臨時寫 pandas）
```bash
python scripts/yewan_cohort.py --data-dir <CSV 資料夾> --output-dir <輸出資料夾>
```
- 需要 pandas、numpy（Colab、Claude 程式執行環境都已內建）。
- 檔名不同時，修改 `scripts/yewan_cohort.py` 最上方的 `FILES`；欄位名稱不同時，在 `COLUMN_ALIASES` 加別名。
- 觀察截止日預設是資料中最後一筆捐款日，可以用 `--as-of` 覆寫。

### Step 2：先讀資料品質，再讀結果
打開 `00_資料品質檢查.csv`，或直接看 `summary.json` 的「資料品質」：
- **ERROR**：停下來告訴使用者，先修資料（例如主鍵重複、外鍵對不到）。
- **WARN**：分析可以繼續，但要在結論裡說明影響。已知的 WARN 和對應處理方式，請見 `references/data_quality_known_issues.md`。

### Step 3：跑驗證測試
```bash
python scripts/test_yewan_cohort.py --data-dir <CSV 資料夾>
```
測試會用另一套程式（只用 Python 標準函式庫）獨立重算關鍵數字，並和管線輸出對帳。**有任何測試失敗，就不要交付結果。**

### Step 4：解讀結果（以 `summary.json` 為準）
- 只從 `summary.json` 和輸出的 CSV 引用數字，**不要心算、不要估計**。
- 每個發現都要對照「判定」欄位：
  - `差異顯著`：可以寫成洞察，但要附上比率、95% 信賴區間和樣本數。
  - `無顯著差異：不宜下結論`：要明確寫出「資料不支持這個差異」。這本身也是有價值的發現，例如「年齡不影響流失，所以不必分齡寫信」。
  - `樣本太少：不宜下結論`：寫出需要補多少資料才能判斷。
- 一次比較很多分群時，用 `校正後p值`（Bonferroni 校正），不要用原始 p 值挑出「顯著」的那一個。
- 各指標的算法定義見 `references/metrics.md`。使用者問「這個數字怎麼算的」時，引用那份文件。

### Step 5：轉成行動
依 `references/analysis_playbook.md` 的對照表，把結果轉成「給誰 → 什麼時候 → 說什麼」。
- 任務二的主要產出是 `t2_優先提醒名單.csv`：每一列都有「建議行動」和「理由」，公益勸募科可以直接依此分工。
- 任務三：如果活動判定都是「無顯著增加」，不要硬湊結論。改為建議「之後怎麼記錄活動，才能量得到成效」，例如捐款頁加 UTM、活動專屬捐款連結。

### Step 6：交付
依使用者需求選擇格式：
- **互動報告**：直接給 `report.html`（表格可排序/篩選、圖表可 hover）。
- **三頁簡報**：用 `references/analysis_playbook.md` 最後的簡報骨架（問題 → 方法 → 組織能不能用）。
- **行銷名單**：`t2_優先提醒名單.csv`，可匯入 Google Sheets。

每次交付都必須回答以下三個問題：
1. 誰、在什麼時刻會打開它？
2. 使用前後有什麼差異？
3. 還缺什麼資料？誰來補？怎麼持續？

## 不可以做的事
- 不可以用 `定期扣款.扣款期數` 算「第幾期停止」，這個欄位不會隨日期遞增，要改用 `定期明細.執行期數`。
- 不可以把 `聯絡人.建立日期` 當成「開始支持的時間」，要用實際首捐日期。
- 不可以把 2025-11 的 Cohort 和其他月份直接比較，這一群混有期間開始前就在捐的舊捐款人（左截斷）。
- 不可以把 `狀態=已完成` 當成「成功扣滿」，大多數已完成方案其實沒有扣滿約定期數。
- 不可以把 Cohort 熱圖中的空白格當成 0，空白代表還無法觀察。
- 不可以把 `活動時間軸` 寫成野灣的真實活動，它是虛構示意。
- 不可以因為「看起來有差」就下結論，一定要看判定欄位。
- 不可以把「同一人有多個定期方案」直接解讀成加碼或回流。野灣換信用卡時必須重新設定新方案（見 `knowledge_base/募款與溝通管道.md`），很多「新方案」其實只是換卡。
- 不可以編造動物故事或組織數字。撰寫信件或簡報時，只能引用 `knowledge_base/` 和年報中的內容。
