# 名詞對照（官方示範資料 ↔ 野灣實際系統）

- 來源：野灣_示範資料_v1.xlsx 的「⑦欄位說明」、官網捐款頁、FAQ
- 整理日期：2026-11-15（改用 AI Impact Day 當天的官方資料）

| 示範資料欄位 | 實際系統（官網會員平台） | 分析時要注意 |
|---|---|---|
| 系統編號（數字） | 會員平台聯絡人 ID，所有分頁用它串接 | ① 有一筆重複；真實資料同樣有 |
| 性別：生理女／生理男／其他 | 捐款或註冊表單 | 沒有捐款紀錄的聯絡人多半空白 |
| 年齡：5 歲一級（未填寫） | 出生日期（**選填**） | 超過一半「未填寫」；25 歲以下比例的分母要用已填者 |
| 鄉鎮市區 | 地址 | 沒有縣市；東區、北區、中正區等跨縣市同名。②③ 的住家-縣市約 96% 空白 |
| 聯絡人建立日期 | 第一次留下資料的時間 | 很多人是捐款當下才建立 → 可用來判斷新、舊捐款人 |
| 捐款編號 | 每筆捐款唯一、依時間遞增；單筆和定期共用 | 主鍵 |
| ② 交易編號「X_N」 | 金流 | 後段 N＝這個方案的第幾期（主辦方解讀）；**不唯一** |
| ③ 交易編號 | 金流交易代碼 | LINE Pay 是很長的數字，其他等於捐款編號 |
| 金流機制（1、3、7） | 金流代碼 | 代碼意義不明，以付款工具為準；④ 這欄是文字（信用卡／LINE / Apple Pay） |
| 定期捐款編號 | 定期定額方案 | 同一人可能有好幾個方案 |
| ④ 一人一列 | 明細只顯示一個方案，常是舊方案 | 要用 ② 的定期捐款編號還原 |
| 執行期數 / 約定總期數「不限」 | 沒有填寫期數 → 持續扣款直到通知停止 | 不是缺漏 |
| 狀態：進行中／已完成／暫停中／待處理／已失敗／已取消 | 會員平台定期捐款狀態 | 主辦方解讀：待處理＝第一次扣款沒成功；暫停中＝扣款一段時間後停下、原因不明 |
| 同一人的多個定期方案 | **換卡需要重新設定新方案** | 不可以直接解讀成加碼或回流；舊方案停止≠流失 |
| 收到金額總計 | 方案累計收到金額 | 包含期間以前的扣款 |
| 捐款來源（沒有這個欄位） | 官網沒有來源欄位 | 需要 UTM／活動專屬連結才能歸因 |
| 活動時間軸 | 虛構 | 真實活動請參考年報 |
